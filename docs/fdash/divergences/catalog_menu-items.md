# Catalog menu / items (`/menu/items`): differences from the web

One line per difference: what the web does, what Flutter does, why. Rows marked "question" port
the web's behaviour as it is and ask the owner.

| Row | Web | Flutter | Why |
|---|---|---|---|
| MENU-ITEMS-009, 042, 057 a failed list read | No error state: a failed catalog / add-ons / categories read renders the empty state ("No items yet", …), as if there were nothing. | "Couldn't load this" with the server's words and Retry (only that read is refetched; the button spins while it runs); the empty words only for a real empty answer. The toolbar stays. | Presenting a failure as "nothing here" misleads (SPEC 6.3; the unit brief's loading/error/empty rule). Pinned by "MENU-ITEMS-009 / 042 / 057 (divergence) …". |
| MENU-ITEMS-087 edit with no sizes yet | Edit mode opens with `sizes: []` until the full item lands (and stays empty if that read fails); Save fails the array rule with nothing on screen: no message, no toast, no request. | The same validation, but "An item needs at least one price." (`menu.needsOneSize`) shows under the Sizes section. | A Save that silently does nothing is the worst outcome a form can have (SPEC 6.1). Pinned by "MENU-ITEMS-087 (divergence) …". |
| MENU-ITEMS-083 upload errors | A failed upload (or Remove) shows the raw JS error under the box: Axios's "Request failed with status code 413". | The server's words (`ApiException.message`) under the box. | Raw transport errors shown to people are a web bug. Pinned by "MENU-ITEMS-083 (divergence) …". |
| MENU-ITEMS-090 picker headers | Each add-on type's header is the humanized raw type ("Milk", "Coffee", "Extra"), English in Arabic too. | The type's shared group name in the active language ("اللبن"); the humanized type only when no group carries the type. | English inside the Arabic UI; the header names the group the type stands for. Pinned by "MENU-ITEMS-090 (divergence) …". |
| MENU-ITEMS-110 raw names | The delete confirms' titles, the duplicate toast, the add-on recipe dialog's description, the item dialog's add-on chips and picker chips, and the add-on dialog's Group select print the raw (English) `name`, also in Arabic. | The active language's name (`getTranslatedName` rule) everywhere. | English names inside the Arabic UI are a web bug. Pinned by "MENU-ITEMS-110 (divergence) …". |
| MENU-ITEMS-084, 086 "(EGP)" | The price boxes' labels hard-code "Price (EGP)", also in Arabic. | "Price (<currency>)" with the active language's currency word (`currencyLabel`): "السعر (ج.م)" in Arabic, as the paste column already does on the web. | Untranslated English in the Arabic UI. |
| MENU-ITEMS-086 size placeholder | The Label box's placeholder is the English literal "Large". | A word in the supplement (`menu.sizeLabelPlaceholder`: "Large" / "كبير"). | Untranslated English in the Arabic UI. |
| MENU-ITEMS-084, 086, 099 number boxes | `<input type=number step=0.01 min=0>`: the browser blocks a submit with a negative or a third decimal and shows its own tooltip. | The boxes only take digits and one point with two decimals (a minus or a third decimal is not typed), so the blocked states cannot arise. | The browser's native tooltip has no Flutter twin; refusing the keystroke keeps the same rule. |
| MENU-ITEMS-073 re-seeding the edit form | Every new `liveItem` object re-replaces the sizes and the add-on selection, also after the person has typed (a background refetch, e.g. after an image upload invalidates `/menu-items`, wipes the edit); the name, description, category and Active come once from the opener's (possibly older) `item`. | Each fresh read of the item (the cached copy, then the background refresh `ref.webCache()` starts on data older than 30 s) re-seeds every field, sizes, recipe rows and selection, until the person edits the form; then refreshes leave it alone and Save sends the fresh values plus the edit. The category and add-on dialogs re-seed the same way from fresh list reads. | A refetch that erases typing, or a form that saves a stale copy over newer data, is a web bug. Pinned by "MENU-ITEMS-073 / 068 / 093 (re-seed) …". |
| MENU-ITEMS-106 card warm-up area | Hovering (or focusing in) anywhere on an item card, or its ⋯ button, warms `GET /menu-items/{id}` and its studio. | The same reads with the same keys, carried by the card's tile, title and footer (the kit card has no hook of its own, and draws the ⋯ button and the middle fields itself); the pointer entering a card crosses one of them. | Kit candidate (a row hover/focus hook on `DashEditableCardGrid`). Pinned by "MENU-ITEMS-106 …". MENU-ITEMS-107 (Next warms the next page) is ported as is, on the page's own pager. |
| MENU-ITEMS-015 columns | Tailwind's viewport breakpoints: 4 columns from `xl` (1280 px viewport), sidebar or not. | The kit's grid counts columns from its own width: 3 at 1440×900 with the sidebar open. | Kit layout rule (kit candidate); the test pins "a multi-column grid". |
| MENU-ITEMS-043 search fold | `normalize`: full Unicode NFKD, then strips combining marks and Arabic tashkeel. | Lower case, tashkeel and combining marks stripped, and a table of the precomposed Latin letters a menu uses (à…ÿ) folded; no full NFKD (Dart has none without a package). | Same results on every seeded name; a letter outside the table would not fold (`ponytail:` note in `items_data.dart`). |
| MENU-ITEMS-043, 058 search timing | The Add-ons / Categories search filters on every keystroke. | It filters 300 ms after the last keystroke (the kit's search box debounces whenever the page owns the search, which it must for the shared search of MENU-ITEMS-108). | Kit behaviour; no visible difference beyond the delay. |
| MENU-ITEMS-021, 051 the branch lists | The real backend still reads `GET /branch-menu-overrides` and `/branch-addon-overrides` from the legacy tables, while the toggles write the unified `menu_price_overrides`; on a unified backend the switch would not follow its own writes. | The mock derives both lists from the unified table (an item is off when every active size is off at the branch; its priced sizes as `sizes`). | Question: the web plainly intends the switch to show what it wrote; the backend read looks stale. |
| MENU-ITEMS-073 the full item's recipe | `GET /menu-items/{id}` answers `recipes` and `allowed_addon_ids` from the legacy `menu_item_recipes` / `menu_item_allowed_addons` tables. | The mock answers the item's current own recipe lines and the add-ons its shared groups offer (`included_option_ids`, else every option). | Question: same staleness as above; the edit dialog is meant to show the item as it is. |
| MENU-ITEMS-108 shared search | One grid instance for the three tabs, so the Add-ons search and page carry into Categories (and back). | Ported: one page-owned search and page for Add-ons and Categories; Items keeps its own. | Product quirk, ported as is. |
| MENU-ITEMS-050 Type edit | The Type cell edits, but the patch carries nothing; "Changes saved" anyway. | Same. | Product quirk, ported as is. |
| MENU-ITEMS-070, 079 Active on create | The switch is shown but not sent on create (always created active). | Same. | Product quirk, ported as is. |
| MENU-ITEMS-069 "Name (ع)" in Arabic | The synced Arabic of `bilingualField.arabicLabel` reads "{{label}} (إنجليزي)" ("Name (English)") over the Arabic box. | Ported as is (shared table). | Question: a copy defect in the shared `ar.json`; the fix ("{{label}} (عربي)") belongs to the shared i18n. |
| MENU-ITEMS-083 drag and drop | A picture can be dropped onto the image box. | Choose / Replace only: the kit's `DashImageUploader` has no drop target (desktop drops need a plugin the app does not ship). | Kit candidate; the file picker covers the same need. |
| MENU-AREA-011 Esc | The confirm closes on Esc or an outside click. | An outside click cancels (tested); Esc depends on the kit's `showDashConfirm` key handling (not reached in the widget test). | Kit behaviour. |
