# Admin / Users (`/access/users`): differences from the web

One line per difference: what the web does, what Flutter does, why. Rows marked "question" port
the web's behaviour as it is and ask the owner whether it is intended.

| Row | Web | Flutter | Why |
|---|---|---|---|
| ADM-USR-039 locked reason (owner decision) | The locked note prints `locked_reason` raw: "self", "owner", "not_dominant", "not_above", "missing_authority". | Each code is worded in the active language (supplement keys `access.lockedReasons.*`, the backend's own guard sentences); an unknown code reads `access.locked`. | The inventory leaves this to the owner (copy the raw code or word it); worded here because a machine code shown to people is a web bug (SPEC 6.3). **Owner decision** to confirm. Pinned by `person_access_test` "ADM-USR-039 (divergence)…", "ADM-USR-039 an unknown reason…" and `users_mock_test` "locked reasons in words". |
| ADM-USR-038, 051 failed access read | A failed (or refused) `GET /authz/users/{id}` leaves the sheet body empty: no words, no retry. | The sheet shows `common.loadFailed`, the server's words (an uncoded 403 reads `errors.unauthorized`) and Retry, which asks again for that read only. | A failed load must never look empty (SPEC 6.1; the shared table rule). Pinned by "ADM-USR-038 (divergence)…" and "ADM-USR-051…". |
| ADM-USR-058 locked controls | On a locked sheet (or a row the server marks not editable) the Role / Allow / Deny control looks enabled; taps do nothing. | The control is visibly disabled (and still sends nothing). | A control that silently does nothing is a web bug (SPEC 6.1). Pinned by "ADM-USR-058 (divergence)…". |
| ADM-USR-055 double tap | A Branch Access switch stays live while its call runs; a second tap sends a second call. | The switch is disabled until its call (and the refetch) lands: one tap, one call. | Duplicate writes from an impatient tap are a defect. Pinned by "ADM-USR-055 (divergence)…". |
| ADM-USR-008 role search | The search matches the RAW role value (`branch_manager`), never the words on screen ("Branch Manager", "مدير فرع"). | Both the raw value and the translated label match. | Searching for what the screen shows is the evident intent; the raw value still matches, so nothing the web finds is lost. |
| ADM-USR-053 phone direction | The dialog's Phone box is plain text: in Arabic "+2010…" renders as "…2010+". | The Phone box is left to right in both languages. | Bidi-garbled numbers are a defect; the table already shows the number LTR. |
| ADM-USR-021..027 validation timing | zod runs the role-dependent checks (PIN required, email/password required) only after the field checks pass, so a blank Full Name hides "PIN is required" until it is filled. | Every check shows on the first Create. | Showing all problems at once is the evident intent; the words and the rules are the web's. |
| ADM-USR-034, 038 branches for a branch manager | — | The branch lists (Branch Access, Where) are the core mock's `GET /branches`, which answers a branch manager with their own branches only. | Matches the backend's branch scoping; noted because the web's own mock differs. |
| ADM-USR-053 question: Cancel while saving | The dialog's Cancel stays enabled while Create / Save runs; closing does not stop the call. | Ported as is. | Unsure whether intended. Owner question. |
| ADM-USR-053 question: untrimmed name | Full Name is not trimmed before it is sent. | Ported as is. | Unsure whether intended (the backend's till-name uniqueness compares lowercase, not trimmed). Owner question. |
| ADM-USR-057 question: Why? after a failure | A failed explain toasts and the popover keeps its skeleton until it is closed and reopened. | Ported as is. | The toast says what happened; reopening asks again. Owner question whether an error line is wanted. |
| ADM-USR-035, 042, 047 failed refetch | — (the web's `invalidateQueries` / `refetch` never throw, so a saved change never reads as failed) | Same: the refetch after a successful write is awaited outside the write's error handling; a failed refetch keeps the last answer on screen and toasts nothing. | Parity; noted because an earlier port toasted it. Pinned by "… a failed refetch after a saved change …" tests. |
