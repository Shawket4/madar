# Setup / QR codes (the codes section of `/settings/links-qr`): differences from the web

One line per difference: what the web does, what Flutter does, why. Rows marked "question" port
the web's behaviour as it is and ask the owner whether it is intended. Reviewed against the web's
Links & QR codes change (da5faf63, 2026-11-06): the web now drops a branch card's code on a branch
switch and drops a late table run itself, so the old SET-QR-027 and SET-QR-021 rows are gone.

| Row | Web | Flutter | Why |
|---|---|---|---|
| SET-QR-028 failed tables read | A failed `GET /branches/{id}/tables` shows "This branch has no tables yet. Add them on the floor plan first." — no error, no retry. | The card shows the load-failed state ("Couldn't load this" + the server's words + Retry, refetching only the tables). | A failure that reads as "nothing here" is a web bug (SPEC 6.3). Pinned by `table_codes_test` "SET-QR-028 (divergence)…". |
| SET-QR-012 over-length | zod's default message, in English in both languages ("Too big: expected string to have <=80 characters"). | The web's own `common.atMostChars` ("At most 80 characters" / "80 حرفًا على الأكثر"). | English inside the Arabic UI is a web bug. Pinned by `codes_section_test` "SET-QR-012…". |
| SET-QR-008, 033 warming | A code is a query keyed by its params, fetched only on a press (`enabled`); nothing warms it. | The same keyed read (`qrCodeProvider`, `qrTableSheetProvider`), also warmed when a pointer rests on Generate / "Make codes" / a "QR code" button (owner rule), so the press answers from that read; a second press fetches again, as the web's `refetch`. | Intent warming is the app-wide rule; the warm read is the exact read the press makes. Pinned by `qr_intent_test`, `links_intent_test`. |
| SET-QR-033 cache time | `gcTime` 10 min for a code nobody shows. | The app's 5-minute keep (`ref.webCache`, `kQueryGcTime`) with a stale time of a year (the web's `staleTime: Infinity`). | One cache policy for every read; a code flipped back to within 5 min still answers at once. |
| SET-QR-023, 036 print | Copies the codes into a print-only root; `@media print` CSS hides everything else and sizes them in mm; `window.print()`. | An A4 PDF of only the codes, laid out by the same rules (one code at its real size; sheets 3 a row at 60/50 mm or cards 2 a row at 92 mm; 6 mm column and 8 mm row gaps; branded sheets with a 0.3 mm dashed #9ca3af cut line and the label at 14 pt), handed to the system print dialog (`printing`). An unbranded PDF holds the images and nothing else (no text, no line, no font). Page margin 8 mm. | No browser print in a Flutter app; the PDF reproduces the print stylesheet. Pinned by `qr_print_test` and `table_codes_test` "SET-QR-036 …" (the PDF's drawing is read: images only). |
| SET-QR-036 print name | No job name. | The print dialog's job is named for the code ("All-branches QR", "Table codes"). | The system dialog asks for one. |
| SET-QR-037 share | `navigator.share` where the browser has it (a phone, Safari): the file where files can be shared, else the link. | The system share sheet with the image file and the short link as its text, on Android, iOS, macOS and Windows; no Share button on Linux (no share sheet there). | `share_plus` through the app's file gateway; Linux has no sheet to hand it to. |
| SET-QR-025 buttons | Two a row on a phone, all in one row from 640 (four with Share). | Two a row whenever there are four (with Share), one row of three without it from 640. | Four kit buttons in the 448-wide dialog cut "Copy link" short at the app's type size. |
| SET-QR-015, 018 narrow result | Beside the form from 1024, the 256-px result card puts Print and Download side by side under Copy link. | Copy link, then Print and Download beside each other only when the card is at least 260 wide: in the 256-px card they stack. | Side by side, "Download" was cut short at the app's type size (seen in the walk). |
| SET-QR-013, 033 veil | A spinning RefreshCw over the dimmed code. | The kit's progress ring over the dimmed code (`QrBusyVeil`), which honours reduced motion; its words ("Updating the code…") are announced in the preview, not inside the result's "Enlarge" button (whose label is what a screen reader reads). | Kit control. |
| SET-QR-029 sample | The sample image is the image's own proportions (`max-h-44`). | A square box for the plain and receipt codes, the A6 proportions (105:148) for the card. | The image's own size is not known before it decodes; the shape is. |
| SET-QR-035 Brand link | A text link to `/settings/brand`; from a code's preview the dialog unmounts with the page. | The kit's link button; from a preview it closes the dialog first, then opens Brand. | Dialogs sit on the root navigator above the page. |
| SET-QR-012 in-mall warming (question) | No warming: one call per press. | The in-mall Generate is never warmed; every other code is. | The QR GETs are get-or-create (MadarRust qr_card/db.rs): warming the in-mall card would create a permanent Shlink link per typed place/floor/unit. Owner question: should these GETs have no side effects (create only on an explicit press), so every card can be warmed? |
