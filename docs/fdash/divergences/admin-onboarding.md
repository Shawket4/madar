# Admin / Onboarding (`/onboarding`): differences from the web

One line per difference: what the web does, what Flutter does, why. Rows marked "question" port
the web's behaviour as it is and ask the owner whether it is intended.

| Row | Web | Flutter | Why |
|---|---|---|---|
| ADM-ONB-030 owner's branch | Uploading the café logo calls `setSelectedOrg(orgId, logo)` for everyone; for an owner (whose picked org is normally empty) that counts as an org change and clears the persisted branch selection. | Only a platform admin's picked org takes the new logo (same org, so the branch stays); an owner's branch pick is untouched, and the shell's org and brand reads are refreshed so the sidebar logo follows. Pinned by `onboarding_steps_test` "ADM-ONB-012/030 …" and "ADM-ONB-030 a platform admin's picked org …". | Losing the branch selection as a side effect of a logo upload is a web bug (SPEC 6.3); the intent is "the shell shows the new logo". |
| ADM-ONB-012 upload error | A failed logo upload shows the thrown error's raw text under the picker (ADM-APP-127). | The same place shows the transport's words for the refusal (`errorMessage`, as every toast does). | Raw transport text is a web bug (SPEC 6.3); same rule as ADM-ORG-042 (`admin-orgs.md`). |
| ADM-ONB-021, 022 step reads | The menu-items step reads the categories and the recipes step the items with `data ?? []`: while the read is in flight, or after it failed, the step shows its empty line ("Add a category first…" / "Add a menu item first…"), and a failure is never said. | A skeleton line while the first answer is pending; a failed read shows "Couldn't load this" with the server's words and Retry (refetching only that read, spinning while it runs); the empty line only for a real empty answer. Pinned by "ADM-ONB-021 while the categories load…", "ADM-ONB-021 a failed categories read…", "ADM-ONB-022 a failed items read…". | A failure shown as "nothing here" is a web bug (SPEC 6.1/6.3). |
| ADM-ONB-019, 021 price words | The add-on's default price, an item size's price and a choice-group option's price use zod's built-in English messages ("Too small: expected number to be >=0", "Invalid input: expected number, received NaN"), in both languages. | Supplement keys `onboarding.form.priceMin` "Enter an amount of 0 or more" / `onboarding.form.notANumber` "Enter a number", with Arabic. | English in the Arabic UI and library wording (SPEC 6.3). |
| ADM-ONB-024 gate cache | "Open my café" seeds the shared `/orgs/{id}/onboarding` query with the server's answer synchronously (`onboarding-page.tsx:73-89`), so the shell's gate sees `completed: true` at once and lets the owner through on landing. | The page and the gate share dashboard_core's one checklist read (`onboardingStatusProvider`), but nothing is written into it: the page marks this session as past the gate at once (the session's skip flag, the same thing "Skip for now" sets) and the gate reads again in a later session. Landing on the dashboard never waits on, or bounces off, that read. Pinned by "ADM-ONB-024 a slow gate read after Open my café …". | Same outcome as the web's synchronous cache seed; without it a slow or failed gate read sent the owner back to the wizard under the celebration. |
| ADM-ONB-016..022 inline editors | The steps open the menu, inventory, payment-method and recipe areas' own dialogs. | The same dialogs, ported inside the onboarding unit (`lib/src/onboarding/dialogs/`), because area packages do not depend on each other. Create mode only for payment method, ingredient, category, add-on and choice group (the only mode onboarding opens); the item editor in both modes. The recipe builder, category and ingredient dialogs and the group form model are copies of the catalog_menu ports, so their logged divergences (`catalog_menu-recipes.md`, `catalog_menu-groups.md`) apply here too. | Architecture (SPEC 3/4); kit candidates in the report. |
| ADM-ONB-019 group editor | The add-on dialog's "New group" opens the full choice-group editor, which for an existing group also offers usage, "Manage…" and read-only viewing. | The editor is ported for a new group (everything a new group shows: name, effect with the swap category, pick rule, options with price / Active / Default, swap ingredient, deducted lines, per-size amounts). The edit-only parts are not reachable from onboarding and are not ported. | Scope: onboarding never edits an existing group. |
| ADM-ONB-021 question: Active on a new item | The item editor shows an Active switch on a new item, but `createMenuItem` has no `is_active`: a new item is always created active whatever the switch says. | Ported as is. | Unsure whether intended (a silently ignored switch). Owner question. |
| ADM-ONB-016, 021 question: literal samples | Placeholders "e.g. visa_card", "Visa Card", "فيزا" and the size label "Large", and the " (EGP)" after "Price", are literal in both languages (the org's own currency is not used). | Ported as is. | Literal samples on the web; unsure whether "(EGP)" should follow the org currency. Owner question. |
| ADM-ONB-014 question: owner rename | `PATCH /orgs/{id}` is super-admin only, so an owner's "Save & continue" on the café step always fails with "You don't have permission to perform this action." | Ported as is (the mock refuses the same way). Pinned by "ADM-ONB-014 (refusal) …". | The backend's rule; the step looks broken to an owner. Owner question. |
| ADM-ONB-024 emoji | "Your café is open! 🎉" renders with the platform's emoji font. | Same text; in the test screenshots the emoji draws as a missing glyph because the test renderer loads only the IBM Plex fonts. | Test rendering only; devices have an emoji font. |
