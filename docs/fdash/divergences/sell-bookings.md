# Sell / Bookings (`/bookings`): differences from the web

One line per difference: what the web does, what Flutter does, why. Rows marked "question" port
the web's behaviour as it is and ask the owner whether it is intended.

| Row | Web | Flutter | Why |
|---|---|---|---|
| SELL-BKG-076 timeline loading / failure | While the floor tables load, or after that read fails, the timeline says "This branch has no tables yet / Draw the floor first"; while the day list loads, or after it fails, the rows draw with no blocks. | A skeleton while either read loads; the error state (the server's words + Retry, which asks only the failed read) when either fails. "No tables" only for a branch that really has none. | A failed load shown as "nothing here" is a web bug (SPEC 6.1, SELL-ALL-010). Pinned by `bookings_page_test` "SELL-BKG-076 (divergence) …". |
| SELL-BKG-079 settings read fails | The settings dialog stays on "Loading…" for ever with Save disabled: no error, no retry. | The error state (the server's words) with Retry; Save stays disabled until the settings arrive. | A dead end with no words is a web bug (SPEC 6.1). Pinned by `settings_dialog_test` "SELL-BKG-079 (divergence) …". |
| SELL-BKG-079 edits and a background refetch | Every time the cached settings change while the dialog is open (a stale read refetched on open, a realtime nudge), the dialog re-copies them — also after the person has started editing, discarding what was typed. | The dialog re-copies every fresh read, as the web does, until the person changes something; from then on a refetch no longer replaces their edits. Each opening still starts from the stored row. | A save lost to a background refetch is a web bug (SPEC 6.3, same rule as ADM-ORG-058); a stale copy is never saved over a fresher row before an edit. Pinned by `settings_dialog_test` "SELL-BKG-079 opened on stale settings …". |
| SELL-BKG-026 timeline width | `min-w-[720px]`: on a narrow window, or a whole-day window (a close past midnight), the 12-hour hour labels overlap each other. | Still at least 720 wide, and at least 64 px per hour, so the centred labels never overlap (the board scrolls sideways instead); the lanes keep a half-hour-label inset at the end so the last label is not cut. Pinned by `bookings_page_test` "SELL-BKG-026 the hour labels never overlap …". | Overlapping and cut text is a visual defect (SPEC 6.2); geometry and order are otherwise the web's. |
| SELL-BKG-033 export, a filter matching nothing | The inventory says the file still downloads with headers and no rows; the web's shared `exportToExcel` actually toasts "Nothing to export" and writes no file. | As the web's code: "Nothing to export", no file. | Inventory correction, not a divergence. Pinned by `bookings_page_test` "SELL-BKG-033 a filter matching nothing …". |
| SELL-BKG-004 refetch on focus | React Query refetches the day on window focus only when it is older than 30 s. | The day is re-read whenever the app comes back to the foreground (`AppLifecycleListener.onResume`), plus every 30 s. | Platform: an app resume is the focus event; the extra read is harmless. |
| SELL-BKG-078 question: failed availability | A failed availability read (or a blank party) shows "No booking hours on this day — set a custom time below to force one." — no error words. | Ported as is. | The words still lead to a working path (a custom time). Owner question whether a failed read should say so. |
| Mock: customer on create | The backend creates (or links) a customer for the phone on every host booking. | The mock links an existing customer with that phone; it does not create one. | Mock scope only (`bookings_mock.dart`). |
| SELL-BKG-042/043 custom time on a slot | A typed custom time equal to a slot ("18:00") always reads " · outside the booking slots": the chosen instant (`…:00.000Z`) is compared as a string with the slot's (`…:00Z`), and never matches. | The instants are compared, so a typed 18:00 is the 18:00 slot: no "outside" note, and the slot shows chosen. | The string-shape mismatch is a web bug; the words exist to warn about a time between slots. Pinned by `booking_dialog_test` "SELL-BKG-078 party keeps the time …". |
| Edit dialog re-seed | The edit dialog copies the booking once when it opens and never re-seeds. | An untouched edit dialog follows a fresh read of the day and re-seeds from it; once the person changes a field it stops. | AGENT_BRIEF re-seed rule: a form copied from a stale cache must not save old values over newer data. Pinned by `booking_dialog_test` (re-seed / no re-seed after edit). |
