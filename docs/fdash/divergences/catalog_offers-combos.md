# Catalog offers / combos list (`/menu/combos`): differences from the web

One line per difference: what the web does, what Flutter does, why. "kit" rows are behaviour of a
shared `dashboard_kit` widget the page uses (shared packages are frozen; the tests pin what the kit
does today). "question" rows port the web's behaviour (or the platform's) and ask the owner.

| Row | Web | Flutter | Why |
|---|---|---|---|
| OFFR-CMB-036 last page emptied | Deleting the only combo of the last page (page > 1) leaves the page index where it was: the empty state shows, the footer reads "Page 3 of 2" or disappears, and the person is stuck there until a filter changes. | When the server answers an empty page past the end, the list steps back to the new last page, showing the skeleton (never the empty state) until it lands. Pinned by "OFFR-CMB-036 (divergence) …". | A dead end the person cannot leave is a defect, not a design (SPEC 6.3). |
| OFFR-CMB-035 scope dropped | Opening a combo, New combo and "Channels and margin" navigate without the shell's search params, so the scope falls back to All branches and the default period (the editor's price check then reads organisation prices). | The scope is app state (shell SH-07), so opening a combo keeps the branch and period. Pinned by "OFFR-CMB-035 (divergence) …". | Platform: the scope is not in the URL. Losing the picked branch on a click also reads as a web slip. Question for the owner. |
| OFFR-ALL-018 rights not known yet | The list shows "No combos yet" (no New combo) until `/authz/me` answers, then switches to the real page. | The list's skeleton (title, subtitle, table skeleton), nothing asked, until the rights are known; a failed rights read shows the shell's error with Retry (`OffersPageGate`, SH-10). Pinned by "OFFR-ALL-003 / -018 (divergence) …". | An empty state that is not true flashes before the rows; the brief's loading rule (a skeleton, never a blank or an untrue empty state); SH-10 (fixed on the web in v1.4.27). |
| OFFR-ALL-004 failure words | `getErrorMessage` words a failure in the browser (coded sentences, uncoded 403/429, "Kind: " prefix stripped). | The page shows `ApiException.message` as the transport words it: in real mode the core's `answer_words` (the same ladder) plus the web's coded sentences in `CoreTransport`; in mock mode the mock's sentence (`h.refusalWords`). | Platform: the wording lives in the core for every page, in the active language; no second copy in the area. |
| OFFR-CMB-034 search box (kit) | No clear button; every keystroke waits 300 ms, including emptying the box. | `DashSearchInput`: a clear (×) button, an emptied box searches at once. Both trim the text before it is sent (W1). | Kit behaviour shared by every list; question for the kit owner. |
| OFFR-CMB-007 / -008 selects (kit) | A dropdown under the trigger at every width. | A popover on a wide window, a bottom sheet on a phone (`DashFilterSelect`). | Kit phone layout (SPEC 6.1). |
| OFFR-ALL-016 thumbnail | `AssetImage` would show an asset's variants and poll a processing job, but the backend's `ComboSummary` never carries `image`, so the list only ever shows `image_url`. | The tile shows `image_url` (the glyph when there is none or it cannot load); no asset job is polled. | Same result: the asset path is dead code on this list. |
