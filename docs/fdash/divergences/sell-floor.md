# Divergences: sell / floor (`/floor`)

| Row | Web | Flutter | Why |
|---|---|---|---|
| SELL-FLR-053 | An in-app navigation unmounts the floor and clears the 600 ms autosave timer without saving: an edit made in the last 600 ms is lost (only `pagehide`/`visibilitychange` flush). | Leaving the page saves what is pending (the geometry controller flushes on dispose); hiding the app flushes too (`AppLifecycleListener.onHide`, the `pagehide` twin). Pinned by `SELL-FLR-053 (divergence)`. | A save lost on in-app navigation (SPEC 6.3); the hook's own `flush()` says "used before navigating away". |
| SELL-FLR-087 | Undoing a press that moved nothing (no table edited yet) sets the indicator to "Saving…" and it stays there: nothing is sent and the state is never cleared. | Undo enablement as on the web; when the debounce finds nothing to send the indicator goes back to hidden. Pinned by `SELL-FLR-087 (divergence)`. | A "Saving…" that never clears (SPEC 6.3). |
| SELL-FLR-054 | A table's first local edit has the empty snapshot `{}` behind it, which means "the server row". Once that edit autosaves and the floor refetches, the row IS the edited position, so undoing it does nothing visible and sends nothing. | When a table first gets a local edit, its pre-edit geometry is pinned into the existing undo/redo snapshots, so undo puts it back and saves that. Pinned by `SELL-FLR-036/041/054` (undo back to 40, 40 after a save). | Undo that silently does nothing after autosave contradicts the hook's own rule ("undo is itself a change that persists"). |
| SELL-FLR-047 | A delete that fails part-way toasts and skips `invalidateFloor`: the tables already deleted stay drawn until the next refetch. | The floor re-reads after the loop either way. Pinned by `SELL-FLR-047 a table with a live bill refuses…`. | The canvas would show tables that no longer exist. |
| SELL-FLR-072 | A sitting with no money reads "Still open" only for `status = open`; any other status, including a live bill marked `ready`, reads "Voided". | `open` or `ready` reads "Still open". | A live bill labelled Voided is wrong. The backend's ticket enum no longer has `ready` (it became `open` + a `ready` flag), so this only matters for old rows: question. |
| SELL-FLR-016 | Space evenly across shows the character "⇹". | The `arrow-left-right` glyph, same tooltip and label. | The app's fonts (IBM Plex Sans Arabic / Mono) have no "⇹"; it rendered as an empty box. |
| — (branch switch) | Switching branch keeps the lock, the area chip and the selection; a section id from the old branch matches no table, so the canvas shows the empty state with no chip active. | The floor starts afresh per branch (Locked, All, nothing selected, a new undo history). | The kept area id is an artefact, not a choice: the old branch's area does not exist on the new one. |
| SELL-FLR-025 | A table's `<title>` (hover) is "label · N seats · occupant/reservation"; screen readers get no state. | The hover title is the same (a `Tooltip`); the table's screen-reader name adds its state word ("· Reserved"). | State never rests on colour alone (madar CLAUDE.md); a screen reader could not tell a free table from a dirty one. |
| SELL-FLR-081 | The inspector and transfer queue dock beside the canvas at ≥ 1280 (xl) and sit under it below that. | Docked at ≥ 760 (the tablet too), under the canvas on a phone. | The inventory's instruction (as the POS floor screen does). |
| SELL-FLR-020 | The add-table Seats errors are zod's built-in English sentences. | `floor.errSeats` "Seats must be a whole number from 0 to 99" / Arabic, from the unit supplement. | No untranslated text on an Arabic screen. |
| SELL-FLR-059/060/061/048 edit then move | A table edited in the inspector (label/seats/shape/area) cannot then be moved: the PATCH bumps `updated_at`, but `use-floor-geometry.ts:80-83` keeps the token first seen, so the next layout save 409s. | The inspector hands the PATCH response's `updated_at` to the geometry (`FloorGeometry.adoptToken`), so the next save carries it. Pinned by `SELL-FLR-059/048 a renamed table can then be moved`. | Your own edit refusing your own move is a bug (SPEC 6.3); the web has it too. |
| SELL-FLR-059/060 failed save retry | A failed inspector save can't be re-sent with the same value: the de-duplication remembers it as sent. | Coming back into the field clears that memory (Enter-then-blur still sends once). Pinned by `SELL-FLR-059/060 a failed save is sent again from the field`. | A save lost to a transient error (SPEC 6.3). |
| SELL-FLR-045 paste position | ⌘V lands the paste at `view.x + rect.w / 2`: screen pixels added to canvas units, so zoomed the paste lands off-centre. | The view's centre in canvas units (`view.x + width / zoom / 2`), snapped. Pinned by `SELL-FLR-045 zoomed in, a paste still lands in the centre`. | The web's own comment says "land the paste in the middle of what you are looking at". |
| SELL-FLR-016 key hint | The hint reads "⌥ ignores the grid · ⌘C/⌘V". | `floor.hint` names the keys: "Alt ignores the grid · Ctrl/Cmd+C/V" (AR: "مفتاح Alt يتجاهل الشبكة · Ctrl/Cmd+C/V"). | The app's fonts have no ⌥/⌘; they rendered as empty boxes. The canvas honours Alt, and Ctrl or Cmd. |
