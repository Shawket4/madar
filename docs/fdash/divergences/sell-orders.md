# Sell / Orders (`/orders`): differences from the web

One line per difference: what the web does, what Flutter does, why. Rows marked "question" port
the web's behaviour as it is and ask the owner whether it is intended.

| Row | Web | Flutter | Why |
|---|---|---|---|
| SELL-ORD-048 reward minus | en.json `orders.rewardCovers` is "Reward covers {{units}} · −{{amount}}" and the web passes an already negative amount, so the line reads "Reward covers 1 · −−EGP 115.00" (AR the same). | The amount goes in unsigned: "Reward covers 1 · −EGP 115.00". Pinned by `order_sheet_test` "SELL-ORD-047/048/058 …" (no "−−" anywhere). | A double minus is a web bug (SPEC 6.3; the inventory names it). |
| SELL-ALL-017, SELL-ORD-031/069, SELL-ALL-018 error words | `getErrorMessage` maps an uncoded 403 to `errors.unauthorized`, a coded error to `errors.codes.<code>`, strips the "Kind: " prefix, and words by status. | Every error state and toast shows `ApiException.message` through dashboard_core's `errorMessage` (SPEC 3.1: the message is already human, in the active language; in real mode the core words refusals, coded errors included). Tests assert `h.refusalWords(response)`. | The orchestrator's rule for every unit (AGENT_BRIEF): the wording lives in the core transport, not per page. `orders/error_text.dart` (the web's mapping) stays only for the floor unit, which imports it. |
| SELL-ORD-018/033 the "#" column's menu label | The header reads "#", the Columns menu and the phone card read `orders.orderNumber` with the literal "{{n}}" ("Order #{{n}}"). | The kit has one label per column: "#" in the header and the Columns menu; the phone card leads with the ref (no label), as on the web. | The raw "{{n}}" is a web bug; a separate menu label is a kit candidate (`DashColumn.menuLabel`). |
| SELL-ORD-027 predictive loading | Hovering a row prefetches its order; the next page is prefetched when a page arrives and when Next is hovered. | No predictive reads: one list read per page, the order read when its sheet opens. Pinned by "SELL-ORD-027 …". | The inventory leaves it to Flutter ("may prefetch or not; no visible behaviour"); fewer requests on a metered tablet. |
| SELL-ORD-079 export filters | The export call carries every page filter, including `order_type`, `channel` and `exclude_items`. | Those three are not sent: the generated client has no such parameters and `export_orders` ignores them (its query struct lacks them), so the file is the same. | Same server answer; a Type/Channel filter not narrowing the export is the backend's behaviour on both apps (question for the owner). |
| SELL-ORD-074/075 dates in the snapshot and file name | "YYYY-MM-DD → YYYY-MM-DD" and the file name take the first ten characters of the UTC instants, so a Cairo day reads as the previous date ("2026-10-07 → 2026-10-08" for 8 Oct). | The same (ported as is). | question: the workbook meta line uses the branch-zone dates ("08 Oct 2026 → 09 Oct 2026"); the snapshot and file name probably meant the same days. |
| SELL-ORD-017 delivery skeletons | The block shows only when `total_orders > 0`, so its two skeleton cards (loading) can never appear. | The same: the block appears with the data; `OrdersDeliveryChannels(loading: …)` keeps the skeletons for parity. | Ported as is (product choice: no empty delivery block). |
| SELL-ORD-078 guard toasts | "Please select a branch first" / "Please select at least one sheet to export" are coded in the click handler, but the button is disabled in both cases, so neither toast can show. | The same guards in the handler, the button disabled in both cases. Pinned by "SELL-ORD-077/078 …" and "SELL-ORD-077/081 All branches …". | Ported as is. |
| SELL-ORD-056 catalogue freshness | The catalogue read is fresh for 5 minutes (`staleTime: 5 * 60_000`). | The app-wide 30 s stale time (`ref.webCache()`); a sheet opened more than 30 s later refetches the catalogue in the background. | One cache policy (SPEC 6.1); the figures shown are the same. |
| SELL-ORD-016/086 shared delivery report | — | The orders mock seeds the branch's own deliveries in `delivery_orders` (shared with the overview's delivery card, which reads the table when present), and the added sales ring on each branch's Counter 2 (T2) till in that till's own number sequence. | Mock data only: keeps the Orders, overview and Tills figures in agreement. |
| SELL-ORD-002/081 no org in scope | The page renders with the Export button disabled and asks nothing. | The shell's module gate renders nothing until the org's modules are known (SELL-ALL-003), so a platform admin with no org picked sees a blank page; nothing is asked either way. Pinned by "SELL-ORD-002 a platform admin with no org asks nothing". | The module gate is the shell's (same rule as the web's ModuleGate, which also renders nothing until modules are known). |
