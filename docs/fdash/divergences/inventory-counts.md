# Inventory ▸ Stock counts: divergences from the web

Web: `src/features/inventory/{counts-page,count-editor,variance-report-dialog}.tsx` (v1.4.18). Flutter:
`packages/dashboard_features/inventory/lib/src/counts/`. Tests named `(divergence)` pin each fix.

| Row | Web | Flutter | Why |
|---|---|---|---|
| INV-CNT-007 | `<CountEditor stocktakeId={openCount.id}>` has no `key`: switching to a branch with its own open count reuses the editor, whose `hydrated` flag is already set, so the new count's saved figures never load and the typed figures of the first count (keyed by ingredient) stay on screen and are autosaved INTO the second count. | One editor per count (`ValueKey(count id)`): the other branch's count opens with its own figures. | Bug: figures of one branch written into another branch's count. |
| INV-CNT-026 | Figures and reasons are copied from the server once, when the count first loads; a figure another device saves later never shows, and the next edit here re-sends every local figure, overwriting it. | Until the first edit on this screen, each 30 s read re-seeds the figures and reasons (no save); after an edit, polls leave them alone as on the web. | The brief's re-seed rule: a form that copied the value once saves it over newer data. |
| INV-CNT-041 | The autosave timer is cleared on unmount: leaving the page (or switching branch) within 1.2 s of the last keystroke loses that figure. | A save still due when the editor closes is sent. | Bug ("a save lost on in-app navigation", SPEC 6.3). |
| INV-CNT-041 | `flush()` awaits the save in flight once; a second waiter (the debounce and Finalize at the same moment) can find `dirty` already cleared by the first and return while the newer save is still out, so Finalize can POST before the latest figures land. | A flush waits until no save is in flight before deciding. | Bug (race); the web's own comment says finalize must judge the numbers on screen. |
| INV-CNT-045 | A confirmed cancel leaves the 1.2 s autosave armed; if it fires before the list refetch unmounts the editor, the server answers 409 "Cannot edit counts on a finalized or cancelled stocktake" and that shows as an error toast. | A confirmed cancel drops the due save (the figures are being thrown away). | Bug: a spurious error right after a successful cancel. |
| INV-CNT-045 | `invalidateInventory()` runs twice on cancel (the editor's and `onCancelled`'s). | Once. | Same refetch either way; the second call only re-requests what the first already refetches. |
| INV-ALL-006 | No route guard: typing `/inventory/counts` without `inventory.counts.read` renders the page and the list shows the 403 words. | The shell's route gate (`DashRoute.caps`, owned by the shell) shows `Restricted` and reads nothing. A 403 the server sends anyway still shows its words in the table (pinned). | Shell-wide rule (same as Today and Ingredients); not this unit's to change. Question for the owner. |
| INV-ALL-024 | The empty editor's "New ingredient" link navigates without search params, so the branch falls back to All branches. | The scope is kept (it lives in the shell's scope provider, not the URL). | Likely a web bug (the inventory marks it a quirk to reproduce only if the owner confirms). |
| INV-CNT-021, -031 | The pickers (`Combobox`) search the label only; the category hint is not searched (INV-ALL-023). | The kit's `DashOption.matches` also searches the hint, so typing "Milk" in "Add an item…" also offers Milk-category ingredients. | Kit behaviour (kit candidate: a `searchHint: false` switch); not forked locally. |
| INV-CNT-020 | Each category option reads "Milk" with a muted "(5)". | "Milk (5)", one colour. | Kit: `DashOption` has a plain label (its `hint` sits at the far end and is searched). |
| INV-CNT-044 | The footer is `position: sticky` at the bottom of the card. | The same, drawn by moving the footer up to the viewport's bottom while the card runs past it (never above the editor's content). | Flutter has no CSS sticky; local widget (kit candidate). |
| INV-CNT-041 | (question) Clearing a figure sends nothing for that row (the payload carries counted rows only, and the API cannot un-count), so the server keeps the old figure and finalize uses it while the screen shows "not counted". | Ported as is. | Server contract; question for the owner. |
| INV-CNT-053 failed background refresh | A failed refresh of the variance report replaces it with the error. | The report stays on screen; the error shows only while `failedFirst`. | Core loading/error rule (SPEC 6.1). |
