# Inventory ▸ Ingredients: divergences from the web

Web: `src/features/inventory/{items-page,item-dialog,item-drawer}.tsx` (v1.4.18). Flutter:
`packages/dashboard_features/inventory/lib/src/ingredients/`. Tests named `(divergence)` pin each fix.

| Row | Web | Flutter | Why |
|---|---|---|---|
| INV-ING-020 | The Standard cost field (step 0.0001 EGP) is sent as `Math.round(EGP × 100)`: whole piastres. Every save of an edit re-sends the prefilled cost, so a sub-piastre cost is rewritten (Full Cream Milk 4.5 → 4 or 5 piastres/ml; Ice Cubes 0.1 → 0, which reads as "free"). | An untouched cost field sends the stored figure exactly (and, with a new unit, no second cost PATCH); a typed cost is sent to the hundredth of a piastre (`round(EGP × 10000) / 100`), the precision the field's 0.0001 step offers. | Bug: silent data loss on any edit (renaming an ingredient changed its cost; unknown-vs-free matters to every cost roll-up). |
| INV-ING-055 | After the ingredient is created, a failing reorder-level PUT leaves the dialog open with nothing invalidated; Save again re-POSTs the ingredient (409 duplicate name) and, with "New category…", the category (409 key taken). | The dialog remembers what this Save already created: Save again PATCHes the created ingredient with the fields as they are now (no second POST), reuses the new category only while its name is unchanged (a renamed one is created), then retries the reorder levels. When something was created before the failure, inventory is invalidated so the list shows it. | Bug: the person could never finish the save they started, and the new ingredient stayed off the list. |
| INV-ALL-006 | No route guard: typing `/inventory/ingredients` without `inventory.read` renders the page and the catalog read shows the 403 words. | The shell's route gate (`DashRoute.caps`, owned by the shell) shows `Restricted` and reads nothing. A 403 the server sends anyway still shows its words in the table (pinned). | Shell-wide rule (same as Today); not this unit's to change. Question for the owner. |
| INV-ALL-024 | "Count this item" (and "View recipes") navigate without search params, so the branch falls back to All branches and the period to the default. | The scope (branch, period) is kept: it lives in the shell's scope provider, not the URL. | Likely a web bug (the inventory marks it a quirk to reproduce only if the owner confirms). |
| INV-ALL-021 | The search skips a column whose value in the FIRST row is null or not a string/number (TanStack's `getColumnCanGlobalFilter`), for every row; the typed text is not trimmed. | Name, category, raw cost and supplier are always searched; the kit's table trims the typed text. | First-row rule is a web quirk (inventory: port only if the owner confirms); trimming is the kit's. |
| INV-ING-033 | The category badge follows the ingredient's name in the drawer title. | The badge sits at the header's end, beside the close ×. | The kit's `DashSurface` title is text only (kit candidate: a title-trailing slot). |
| INV-ING-028 | (question) Blanking the Standard cost, description, pack or yield fields in Edit sends `null`, which the server's PATCH ignores (`COALESCE`), so the old value stays and "Changes saved" shows. | Ported as is (the mock keeps the value too). | Server contract: a PATCH cannot clear these fields. Question for the owner. |
