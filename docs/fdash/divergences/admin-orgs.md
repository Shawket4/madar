# Admin / Organizations (`/orgs`): differences from the web

One line per difference: what the web does, what Flutter does, why. Rows marked "question" port
the web's behaviour as it is and ask the owner whether it is intended.

| Row | Web | Flutter | Why |
|---|---|---|---|
| ADM-ORG-042, ADM-APP-127 logo errors | A failed logo upload or removal shows the thrown error's raw text under the picker: axios's English "Request failed with status code 403", in both languages. | The same place shows the `getErrorMessage` words in the active language ("You don't have permission to perform this action."). | Raw transport errors shown to people are a web bug to port the intent of (SPEC 6.3). Pinned by `org_dialog_test` "ADM-ORG-042 a refused upload…". |
| ADM-ORG-058 typed values lost | Uploading or removing the logo refetches `/orgs*`, and the dialog re-fills every field from the server row, silently replacing anything typed and not yet saved. | Only the logo follows the server row; what was typed stays until Save or Cancel. Each opening still starts from the stored row (ADM-ORG-041). | A save lost to a background refetch is a web bug (SPEC 6.3). Pinned by `org_dialog_test` "ADM-ORG-058 (divergence)…". |
| ADM-ORG-021, 040, 045, 055, 057 server sentences in Arabic | `getErrorMessage` shows the backend's English sentence (kind prefix stripped) in the Arabic UI too, e.g. "Slug 'x' is already taken" under Slug or in a toast. | In Arabic, an English server sentence is replaced by the Arabic words for its status (`errors.conflict`, `errors.validation`, `errors.notFound`, …); coded refusals and uncoded 403/429 read as on the web. In real mode the core already words refusals in the active language and those pass through unchanged. English is unchanged. | English inside the Arabic UI is a web bug (SPEC 6.3); this is the core's own rule for the same sentences. Pinned by `provision_wizard_test` "ADM-ORG-040 Arabic…" and `orgs_logic_test`. |
| ADM-ORG-026, 042 drag and drop | The uploader also takes a file dropped onto it. | Tap to pick through `FileGateway.pickImage` (the kit's uploader); there is no drop target. | Platform: no drag-and-drop source on the phone/tablet targets. |
| ADM-ORG-031, 046, 048 number inputs | `<input type="number" step="0.1">` with browser spin arrows. | A text field with the decimal keyboard that takes Latin or Arabic digits and one decimal mark; the same 0..100 check and words. | Platform: no spin control; Arabic digits are read as the web's `z.coerce.number()` reads Latin ones. |
| ADM-ORG-059 question: untrimmed editor | The edit dialog does not trim Name, Slug or Currency: a space-only value passes the client check and is sent. | Ported as is (a space-only name is sent). | Unsure whether this is intended; the wizard trims the same fields. Owner question. |
| ADM-ORG-059 question: wizard email | The wizard checks Email as typed: a leading or trailing space reads "Enter a valid email" (the request would have trimmed it). | Ported as is. | Unsure whether intended. Owner question. |
| ADM-ORG-057 question: Arabic-only names | An Arabic-only Organization Name slugifies to an empty Slug, so step 1 stops on "This field is required" under Slug until a Latin slug is typed. | Ported as is. | Product rule of the slug (it is a web address); the empty field is the hint. Owner question whether a transliterated suggestion is wanted. |
