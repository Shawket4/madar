# catalog_menu / groups: divergences from the web

`/menu/groups`, the group editor and the usage dialog (MENU-GRP rows). Each row is pinned by a test
named `<row> (divergence) …` or listed beside the test that covers it.

| Row | Web | Flutter | Why |
|---|---|---|---|
| MENU-GRP-004 loading | While the list loads, nothing renders under the header. | A skeleton block. | SPEC 6.1: loading → skeleton. |
| MENU-GRP-004 a failed read | A failed list read shows the empty state "No choice groups yet" (there is no error state). | "Couldn't load this" (`common.loadFailed`), the server's words and Retry, which refetches the list only. | Web bug: it tells the owner the org has no groups when the read failed. |
| MENU-GRP-049 hidden fields | Hidden fields are still validated: an emptied "Up to…" count hidden by picking Exactly 1 / Any / Swaps, or a blank or zero ingredient line hidden by switching to Nothing / Swaps, blocks Save with no message, no toast and no request. | Only what the form shows is validated (the count while "Up to…" shows, lines while "Adds ingredients" shows them, the swap fields for a swap group). | Web bug: a Save that silently does nothing. |
| MENU-GRP-049 a grid cell of 0 | A per-size grid cell of 0 blocks Save with no visible message (the line's error has no field in the grid). | "Enter an amount above 0" under the grid. | Same bug. |
| MENU-GRP-031 browser validation | The browser's own validation stops 0, negatives and decimals in the count, a negative or > 2-decimal price, and a negative amount before zod runs. | Input formatters do the same: the count takes digits only, the price digits and up to two decimals, the amount digits and one dot (no minus anywhere); zod's messages show for what still gets through ("Must be at least 1", "Enter an amount above 0", a price of "." reads as not a number). | No native form layer in Flutter. |
| MENU-GRP-035 | The one-default rule compares `getValues("up_to") === 1`; once the count has been typed the form holds the string "1", so in an "Up to 1" group turning a Default on no longer turns the others off. | The rule reads the count as a number: "Up to 1" always keeps one default. | Web bug: a typed count silently breaks the single-choice rule. |
| MENU-GRP-026..038 | Validation order: zod's `superRefine` runs only once the plain fields pass, so "Pick the ingredient category this group swaps", "Pick the ingredient this option pours" and "This ingredient is already on this option" appear only after the plain errors (required name, count, amounts) are fixed and Save is pressed again. | Every message shows at once on Save. | Two-step error reveal is a zod artefact, not a product rule; one Save shows everything that blocks it. |
| MENU-GRP-026/034/044 | A failed Save does nothing visible when the first invalid field is scrolled out of the dialog. | A failed Save scrolls the first invalid field into view. | A Save that looks dead. |
| MENU-GRP-031 price messages | zod's default price messages are English in both languages ("Too small: expected number to be >=0", "Invalid input: expected number, received NaN"). | The same words in English, Arabic in Arabic (`menu.groups.editor.priceMin`, `.notANumber`). | English shown inside the Arabic UI. |
| MENU-GRP-034/036/038 | Unit hints next to ingredients and amounts use `fmtUnit` (Latin g / ml / L / pcs even in Arabic). | The translated unit words (`units.*`), as the area's other recipe editors and the shared label grid show them. | English shown inside the Arabic UI; one unit vocabulary across the area. |
| MENU-GRP-050 | Usage dialog: no loading indicator (an empty box until `GET /menu-items` returns), no error state, and an empty bordered box when the search matches nothing. | A skeleton while loading, "Couldn't load this" + Retry on a failed read, "No results found" for no match. | SPEC 6.1 states; an empty box reads as "no items". |
| MENU-GRP-018/050 | Usage dialog item names are the raw English `name`, also in Arabic, sorted by it. | The Arabic name in Arabic when not blank (else `name`), sorted by the name shown (case-insensitive); the search matches either name. | English names inside the Arabic UI. |
| MENU-GRP-013/017 | The delete confirm ("Delete {{name}}?") and the usage dialog title ("Items offering {{name}}") put the group's English `name` into the Arabic sentence. | The group's Arabic name in Arabic when it is not blank, else `name` (an empty Arabic name never leaves "حذف ؟"); the list rows still show both names as the web does. | English names inside the Arabic UI. |
| MENU-GRP-012 | dnd-kit's keyboard sensor (Space, then arrows) reorders from the handle. | The Move up / Move down buttons (also on the web) and the reorderable list's screen-reader move actions; the handle drags with a pointer. | Platform: no dnd-kit keyboard sensor; the arrows give the same keyboard path. |
