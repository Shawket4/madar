# Admin / Branches (`/branches`): differences from the web

One line per difference: what the web does, what Flutter does, why. Rows marked "question" port
the web's behaviour as it is and ask the owner whether it is intended.

| Row | Web | Flutter | Why |
|---|---|---|---|
| ADM-BRA-024 out-of-range hours | zod's own English ("Number must be less than or equal to 168"), in both languages. | The kit's range words in the active language ("between 1 and 168"). | English inside the Arabic UI is a web bug (SPEC 6.3). Pinned by `branch_dialog_test` ADM-BRA-024. |
| ADM-BRA-022, 026 clearing a stored phone or address | A blank box is sent as `null`; the backend `COALESCE`s null, so a stored phone or address can never be cleared. | On an edit, a box emptied of a stored value is sent as `""` (which clears it); a new branch still sends `null`. | Port the intent: emptying a field must empty it, never silently keep the old value. |
| ADM-BRA-034 tax override on a new branch | The POST carries the four rates, which `CreateBranchRequest` does not take, so a platform admin's override on a new branch is dropped without a word. | The rates ride the follow-up `PATCH` with the till settings (only when a platform admin switched the override on). | A save that silently loses what was typed is a web bug. Pinned by `branch_dialog_test` "ADM-BRA-034 (divergence)…". |
| ADM-BRA-036 create retried | If the till-settings `PATCH` fails after the POST, pressing Create again POSTs a second branch. | The made branch is remembered: Create again retries the `PATCH` on it; one branch. A warehouse is one call, so it cannot happen there. | A duplicate record from a retry is a web bug. Pinned by `branch_dialog_test` "ADM-BRA-036 (divergence)…". |
| ADM-BRA-037 cleared number boxes | `z.coerce.number()` turns a cleared Port, Radius, Latitude or Longitude into `0` (a port of 0, a geofence of 0 m at 0,0). | A cleared box is `null` (no value), as ADM-BRA-029 says blank means. | Port the intent. Pinned by `branch_dialog_test` "ADM-BRA-037 (divergence)…". |
| ADM-BRA-018 export, printer with no IP | `"<brand> @ null:9100"` (the word `null`). | `"<brand> @ :9100"`, the table's own reading. | The word `null` in a file for people is a web bug. |
| ADM-BRA-028 Port | `<input type="number">`, shown as typed ("9100"). | A digits-only text box, shown "9100" (the kit's number box would group it "9,100"). | Platform: the kit groups thousands; a port is an address, not an amount. Kit candidate: an ungrouped number box. |
| ADM-BRA-037 layout and phone | Fixed 2- and 3-column grids at every width; Phone is a plain text box. | The pairs stack in the phone sheet; Phone is LTR with the phone keyboard. | Platform (SPEC 6.1 phone layout); LTR digits follow the table's own Phone cell. |
| ADM-BRA-016, 033, 034 server sentences in Arabic | `getErrorMessage` shows an uncoded backend sentence in English in the Arabic UI. | The orgs page's ladder (`orgErrorWords`): coded refusals in their own words (`WAREHOUSE_LIMIT`, `BRANCH_STILL_SELLING`, …), an uncoded English sentence in Arabic replaced by its status words. | As docs/fdash/divergences/admin-orgs.md; English inside the Arabic UI is a web bug. |
| ADM-BRA-038 question: hidden fields on a warehouse | A warehouse hides the printer and tax boxes but the form still sends their values (a printer picked before switching Type to Warehouse is saved). | Ported as is. | Unsure whether a warehouse should keep a printer it cannot show; owner question. |
| ADM-BRA-029/037 coordinates and radius | The number inputs carry no range checks: any latitude, longitude or a negative radius is sent and stored. | Latitude -90..90, longitude -180..180, radius ≥ 0 are checked before Save. | A coordinate outside the globe or a negative geofence radius is never valid; web bug not copied. |
| ADM-BRA-037 radius required | A cleared Radius box sends `geo_radius_meters: null`, which the backend's COALESCE ignores (the old radius silently stays). | Radius is required (default 200): a blank box blocks Save. | A save that says "updated" but keeps the old value is a web bug. |
| ADM-BRA-004 one read | The page's `useListBranches` and the scope bar share one query key, so one request. | The page reads core's `branchesProvider`; `adminBranchesProvider` forwards to it for the scope org. | Same single request as the web. |
| ADM-BRA-006 tablet name cell | Name and Warehouse pill sit on one line, cut by `truncate`; the table scrolls sideways at tablet. | The pill wraps under the name when both don't fit; the table fits without sideways scroll. | Keeps the name visible and the row actions on screen (the kit doesn't pin them). |
| ADM-BRA-019/020 edited branch gone | When the list refetches without the edited id, the dialog unmounts but `?edit=<id>` stays in the URL. | The dialog closes and `?edit` is cleared. | A stale param would reopen the editor unexpectedly. |
