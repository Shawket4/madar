# Setup / Payment methods (`/settings/payment-methods`): differences from the web

One line per difference: what the web does, what Flutter does, why. Rows marked "question" port
the web's behaviour as it is and ask the owner whether it is intended.

| Row | Web | Flutter | Why |
|---|---|---|---|
| SET-PAY-010 failed read | The page passes no `error` to its `DataTable`: a failed `GET /payment-methods` (a 403, a 500) shows the empty state "No results found", as if the org had no methods. | The table shows the shared load-failed state ("Couldn't load this" + the server's words + Retry, refetching only the list). The stats still read 0, as on the web. | A failure that reads as "nothing here" is a web bug (SPEC 6.3; the shared table's own rule, SET-SHL-016). Pinned by `payment_methods_page_test` "SET-PAY-010 (divergence)…" and "SET-PAY-037 a persona without payment_methods.read…". |
| SET-PAY-004 stat columns | `grid-cols-2 lg:grid-cols-4` by the viewport: at 1024 wide, beside the app sidebar and the settings rail, the four cards are ~100 px each. | Four in a row only when the viewport is ≥ 1024 AND the pane is ≥ 640 wide; otherwise two. Desktop (1440) is four, as on the web; the 1024 tablet is two. | The kit's `DashStatCard` loading skeleton is 80 px wide and overflows a ~63 px card body (a layout error); two columns also keep the labels readable. Kit candidate reported. |
| SET-PAY-034 editors reset | `useEffect(() => form.reset(value), [value])`, where a teller's or device's `value` is a new object on every render of the tab: any re-render (another editor's save starting, a query's state changing) throws away unsaved ticks in every teller and device editor. | Every editor goes back to the server's values when the availability read answers again (after a save, a live event or a refetch), and only then. | Unsaved input lost to an unrelated re-render is a web bug (SPEC 6.3). Pinned by `availability_test` "SET-PAY-034 SET-PAY-036…". |
| SET-PAY-012, 019 dialog during a refetch | The open dialog gets `method={editing}` recomputed from the list; when `/payment-methods*` refetches while it is open (a live `payment_methods.availability_changed`, a toggle elsewhere) the form `reset`s, replacing what was typed. | The dialog keeps the method it was opened with; what was typed stays until Save or Cancel. | A save lost to a background refetch is a web bug (SPEC 6.3). Pinned by `payment_methods_page_test` "SET-PAY-019 (divergence)…". |
| SET-PAY-014, 015 placeholders | The placeholders are literals: "e.g. visa_card", "Visa Card", "فيزا" in both languages (English "e.g." inside the Arabic UI). | Supplement keys `settings.pm.idPlaceholder` ("e.g. visa_card" / "مثال: visa_card"), `settings.pm.labelEnPlaceholder`, `settings.pm.labelArPlaceholder` (the examples themselves stay, as they illustrate an English and an Arabic label). | No hard-coded UI text (SPEC 2); English inside the Arabic UI is a web bug. |
| SET-PAY-018 switch cards | Only the label and the switch toggle a switch card. | A tap anywhere on the card toggles it (the switch stays its own 44-pt control). | Touch targets (SPEC 2); same outcome. |
| SET-PAY-029 choice rows | Rows are `min-h-9` (36 px). | Rows are 44 pt tall. | Tap targets ≥ 44 pt (SPEC 2). |
| SET-PAY-022 people read without a branch | With "All branches" the tab still reads `GET /users?org_id=` (the hook runs before the branch check) though nothing uses it. | The same request is made. | Ported as is (it warms the cache for the moment a branch is picked). |
