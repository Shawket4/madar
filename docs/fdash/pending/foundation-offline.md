# Foundation B: offline persistence + range inference (owner requirement beyond the web)
A previous agent built part of this (a store and the transport wrapper in dashboard_core/dashboard_api; it was about to write the store and transport unit tests) when the API dropped it. Find its work first (`git log -3 --stat`, `git diff HEAD~3 --stat`, grep for "offline" in packages/dashboard_core/lib and packages/dashboard_api/lib), keep what is right, and continue.

The owner's words: "I want it even if fully closed and relaunched to show the latest data it has with an indicator that it's offline and that data maybe outdated, this also includes smart inference for example if we fetch mtd and have it cached and then we filter from 1st to 8th of october for example then we have the most up to date data and it's not a problem … obviously when there is network all goes through the prefetching and live apis to prevent stale cache hits."

Build at ONE seam (the transport), so no feature unit changes:
1. Persist every successful GET response (raw decoded JSON body) to disk, keyed by signed-in user id + org id + scope headers (branch) + language if the body depends on it + method + path + sorted query, with its saved-at time. Bound the size (LRU past N MB); write off the UI thread. Wipe all of it on sign-out and on a user switch (it holds salaries and payroll; report where it lives and how it is protected). Never persist export-header requests (X-Madar-Export), streams (Basira) or auth secrets.
2. Online: exactly as now. Saved data is never served in place of a live answer; in-memory webCache rules unchanged.
3. Offline = a request fails with a NETWORK error (not an HTTP status; reuse the core's notion of offline, and a 403 without the backend's error envelope counts as offline): answer with the saved body for that key if any, and mark the app offline with the saved-at time; with none, the normal offline error.
4. Offline banner in the shell: "You're offline. Showing data saved at {time}; it may be out of date." in EN and AR (MSA), words in the core tables. Shown while any shown data came from disk; when a request succeeds again, clear it and refetch the active reads (QueryCache's refetch-active helper if it exists by then, else invalidate active entries). Realtime reconnects as today.
5. Cold start offline: relaunching with no network restores the saved session (stored token) and the shell's reads (me, authz, orgs, branches, modules, nav, onboarding status) from disk, lands on the last/home page with the banner, and never throws the person to sign-in just because the token can't be checked. A real 401 while online still signs out. A first-ever sign-in needs the network.
6. Writes while offline fail at once with a clear "You're offline, so this can't be saved" toast through the existing error wording. No queuing.
7. Smart range inference: a registry of EXACT derivers. For a GET whose answer can be computed exactly from a saved/cached answer for a wider range (per-day or finer breakdown, or the full unpaginated row list, with every figure recomputable: sums yes, averages only with counts, distinct counts and top-N never): online only from a wider answer fetched live < 30 s ago (kQueryStaleTime), treated as a fresh cache hit; offline from any saved wider answer, with the banner. Go through the date-range GET endpoints (reports, overview home, orders summaries, inventory reports, team reports); register derivers only where provably exact; list rejected endpoints with reasons. Each deriver gets a test comparing derived vs the MockServer's own answer over many sub-ranges (single days, month starts, Cairo-midnight crossings, empty days), equal on every field.
8. Tests: offline-after-online shows saved data + banner; online never shows saved data in place of live; cold-start offline restores session + shell reads; sign-out wipes; export/stream/write never persisted; offline write refusal; recovery clears the banner and refetches; size bound; derivers' exactness. Simulate network failure through the transport (a MockServer "network down" switch if none exists).
